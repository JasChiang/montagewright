# montagewright

*-wright*：造船的是 shipwright，寫戲的是 playwright。這個做蒙太奇。


一個資料夾的毛片進去，一支剪好的片出來，以及每一個決定的完整交代。

```bash
montagewright render RUSHES/ --brief BRIEF.md --music TRACK.mp3 \
  --aspect 9:16 --review --output CUT/

montagewright transcribe VIDEO.mp4        # 只要字幕，不重剪
montagewright-web                         # 同一件事，看得到過程與每顆的理由
```

## 這是什麼

一條把「決定」跟「執行」分開的剪輯流程。Gemini 決定這支片是什麼，本機程式決定那落在哪一格畫面上。

| 問題 | 誰回答 |
|---|---|
| 這顆能不能用、裡面有什麼 | Gemini，一支素材看一次 |
| 這批東西該剪成什麼 | Gemini，看完全部加音樂加 brief |
| 用哪幾顆、什麼順序、為什麼 | Gemini |
| 每顆多長、要不要切在拍點上 | Gemini，聽著那首歌 |
| 用什麼運鏡、主體擺在哪 | Gemini |
| 說了什麼、誰說的 | 系統辨識器量時間，Gemini 改文字 |
| 拍點實際落在哪一毫秒 | 本機音訊分析 |
| 主體實際在哪一幀的哪裡 | SAM propagation，種子來自 Gemini |
| 裁切能走多遠、代價是什麼 | 本機算術 |

分工的理由不是信任問題，是**兩邊各自只答得出一種問題**，而錯誤幾乎都來自問錯邊。

## 兩種素材

**畫面剪給音樂。** 一批毛片、一首歌，切點對上實際量到的重音，運鏡在裁切框裡完成。

**話剪給內容。** 訪談、對鏡頭講話、旁白。卡片會說這支素材的聲音是不是內容本身，只有是的才做逐字稿。一顆鏡頭於是變成一句話：進點是那句開始，長度是那句講完要多久，主體是正在講話的那個人。原音保留，音樂壓在人聲底下。

不用先說是哪一種，卡片會說。

## 一輪跑了什麼

```
clip cards   一支素材一張，內容定址快取，刻意看不到 brief
transcripts  只有卡片說「聲音是內容」的素材才做
direction    全部素材 + 音樂 + brief → 調性、長度、比例、音樂怎麼待
selection    可用素材 + 定調 → 哪幾顆、多長、什麼運鏡、為什麼
rhythm       那首歌 + 每顆的用途 → 長度與切點
subject      卡片的框，或一次即時定位
reframe      能量預算內的裁切路徑
render       分段、串接、混音、預覽
review       逐顆對照它自己的宣告，再看整支
replan       沒做到的那幾顆重新規劃，其他不動
```

卡片刻意不看 brief。同一批素材要出第二支片時，看著 brief 寫的卡片得重寫，看著素材寫的卡片還是對的 —— 那才值得快取，而快取讓主體框在每次重跑都免費。

一支已經剪過的長片丟進來，會先照它自己的場景邊界拆開；一支連續的長鏡頭則原樣保留。

## 輸出

`report.json` 有全部：定調、選片與每顆的理由、哪幾刀落在音樂上、每一筆降級與逼出它的量測值、逐顆放大倍率、以及分階段花費。

`--timeline premiere|finalcut|both` 另外寫一份可編輯的時間軸，指回**原始素材**（所以每顆前後的餘量拉得出來），每顆掛著 marker 寫明為什麼選它、為什麼這個長度、哪裡降級、驗收看到什麼。預設不寫。

有逐字稿的話，網頁介面可以下載對齊成片的 SRT。

## 學費買到的東西

**Prose asks; structure binds.** 模型會用它自己的 0..1000 座標回答框的位置，不管欄位描述寫得多堅決 —— 所以轉換在收到的時候做。一個條件必填的欄位標不了 required，只好用必填字串加哨兵值。在重複項目裡要一句短說明，會回來一段 7453 字並撐爆兩個輸出上限。

**只活在 validator 裡的約束是之後才付的帳。** 舊系統有五個，每一個都花掉一次完整的付費規劃才被發現，因為模型無從得知。現在 `schema.py` 裡每個耦合都寫在模型讀得到的地方。

**欄位加在用的地方，不是決定的地方。** 發生過六次：`pan_hint`、`composition`、`subjects`、`min_visible`、動作起訖、`unusable_reason`。每一次都是定義了、下游消費了、上游拿不到。不會有東西壞掉 —— 預設值看起來合理，渲染成功，而決定悄悄從企劃層搬到了一個常數上。

**執行層裡的數字通常是偽裝成量測的品味。** `MIN_DIRECTNESS` 把計畫好的跟拍變成靜止而不說。`MAX_UPSCALE` 替剪接回答「這顆值不值得放糊」。`MUSIC_UNDER_VOICE_DB = -12` 是從音樂自己的音量減下去的，跟人聲一點關係都沒有，結果床比人聲還大聲。可行的形狀是：本機提供選項跟各自的代價，企劃層挑一個，任何替換都連同逼出它的量測值一起記錄。

**執行層不能改企劃層選的運鏡。** 一次 replan 為了避免字被切而改選 hold，執行層轉頭把 hold 換成掃描 —— 下一輪審查於是回報「掃過去了，字還是被切」，迴圈在跟自己打架，而企劃層看不到對手是誰。

**規則要說出它的條件。** 「觀眾聽答案就知道問題是什麼」只有在字卡承載前提時成立；寫成通則就把街訪裡主持人的問句全部刪光，開場變成一句沒有前提的答案。`must_be_whole` 同理：它是一句宣告，不是一個開關，沒有任何裁切能把主體縮小塞進畫面。

**「不會太快」跟「看得懂」是兩個不同的測試。** 三台手機 1.5 秒掃過去符合每一條速度限制，而觀眾還沒看到第二台。

**看畫面。** 這裡每一個構圖 bug 都是抽格看出來的：掃過頭跑進背景牆的 pan、瞄準畫面中央而不是主體的推近、被裁成「y Unpacked」的字樣、框到主持人背影的訪談。而它們在報表上的行程、靜止、對點數字全部正確。

**成片答不出逐顆的問題。** 六個構圖錯誤連續通過整支片的審查，每一個都是單獨打開一顆才看到 —— 三十秒的片子裡，下一顆會蓋掉上一顆的錯。

## 需要什麼

Python 3.12、ffmpeg、`GEMINI_API_KEY`。SAM 追蹤要 checkpoint（`--sam-checkpoint`）。逐字稿要 macOS 26，並先建一次 Swift 工具：

```bash
swiftc -parse-as-library -O -o tools/transcribe/transcribe \
  tools/transcribe/Transcribe.swift
```

## 舊的那套

`src/jascue_video_lab/` 剩下八個模組，全部是量測：SAM propagation、音樂分析，以及它們依賴的 geometry、media、models、shots、storage。上面那層決策程式已經移除 —— 它把決定寫在程式裡，而那些決定累積成了特例，那正是重寫而不是延伸的理由。設計紀錄留在 `docs/history/`。
